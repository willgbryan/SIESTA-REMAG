# Implementation and next residency boundaries

The reference is upstream SIESTA 5.4.2 at `e486d12067b96ff688179f0496d0ec21b6fae0ab`, built independently from an unmodified checkout. The candidate is created with `scripts/patch_siesta.py` from a disposable copy. This exact-match patch refuses repeat application; it does not change the reference checkout.

The initial profiling found that `vmat` and `rhoofd`, not diagonalization, dominated the Fe16 and Fe54 regression workloads. The integrated grid implementation therefore accelerates those operations in addition to establishing a cuSOLVER path. Both retain the upstream numerical definitions and spin representation.

## Grid state

The grid path consumes upstream orbital values in their original FP32 storage and computes contractions in FP64. Basis values, grid-to-orbital lists, periodic translations and sparse indexing stay on device. The patched `dhscf_init` and `dhscf_reset` announce geometry epochs; upstream calls initialization after every geometry change. Within an epoch, matching dimensions and source addresses reuse the staged basis without scanning its contents. Changed epochs, layouts or addresses revalidate content, including when the Fortran allocator reuses an address. This contract applies to immutable grid topology/basis only; density mutations still require the snapshot guard below.

`REMAG_GRID_VERIFY_EPOCH=1` hashes even epoch hits and aborts on an unannounced mutation. `REMAG_GRID_EPOCH=0` restores the conservative content-hash path for ablation. Unversioned native callers (epoch zero) also use that path. Counters distinguish epoch hits, bytes scanned on the host, bytes of host scanning avoided, and actual basis uploads. Geometry lifetime tests and relaxation regression are required before accepting changes to invalidation sites.

Density construction reduces all orbital-pair contributions to each grid subpoint. For full SOC, components 3/7 and 4/8 are averaged exactly as in upstream `rhoofd`. Potential assembly adds to the existing sparse matrix and duplicates the off-diagonal potential components into the corresponding SOC blocks exactly as in upstream `vmat`. FP64 atomic accumulation changes addition order and is checked against upstream observables rather than bitwise values.

The topology currently uses a bounded dense integer lookup from a unit-cell orbital and supercell neighbor to the original sparse index. Electronic matrices remain sparse. The lookup is capped at 512 MiB and fails explicitly above that size; CSR or orbital-block indexing is the next layout experiment. It is not yet appropriate to generalize this representation to very large sparse systems.

## Electronic solve

The native Fortran diagonalization boundary passes the Hermitian Hamiltonian and positive-definite overlap to cuSOLVER. Cholesky factorization, standard-problem reduction, eigensolution and back-transformation occur in one device interval. Real and complex cases use separate reusable buffers. Only the requested eigenvectors are copied back. The current implementation computes the full spectrum even when the upstream caller needs a subset.

The candidate supports one process with full local matrices and exactly one visible GPU. GPU failures, invalid overlaps and unsupported layouts abort with explicit status. `REMAG_GPU=0` is an explicit debugging choice; automatic fallback would make benchmark interpretation ambiguous.

## Resident density matrices

`REMAG_DM=1` enables a second integration stage for the serial `diagg`, `diagk`, `diag2g/k` and `diag3g/k` paths. The Fortran density builder explicitly arms a one-use eigenvector slot before the solve. The two real Gamma spin channels have separate slots; complex k-point and spinor solves consume one slot at a time. Dimensions, type, vector count and lifetime are checked. Unarmed calls keep the original host-output contract, and wavefunction-export requests still receive host vectors.

cuBLAS transposes the retained eigenvectors into orbital-major rows with contiguous state coefficients. A CUDA warp reduces the occupied-state contributions for each existing sparse orbital pair. Density and energy-density matrices accumulate across k points on device; the latter includes the eigenvalue weight needed for forces. Occupations, occupation cutoffs, k-point weights and eigenvalues come from upstream. Both matrices are copied back once per density build for the remaining CPU consumers.

Periodic complex phases follow the upstream convention. Non-collinear calculations symmetrize the off-diagonal spin blocks, while SOC preserves all eight real components of the general spinor density. Energy-density matrices retain upstream's four-component convention. No dense electronic density matrix is introduced.

Upstream normalizes the completed density and energy-density matrices to the required charge. The bridge mirrors that scalar operation on the retained copies only after verifying that the host arrays are exactly the previous outputs multiplied by that scalar. The grid stage borrows the retained density only when every input byte matches the verified snapshot. Host mixing, geometry/layout changes or other transformations therefore invalidate reuse instead of accidentally consuming an old state. Counters distinguish successful reuse, avoided transfers and normalization cache misses.

The opt-in `REMAG_NORMALIZE=1` experiment instead arms a one-use normalization request at `compute_dm`, computes the sparse charge trace and D/E scaling on device, and exports already-normalized arrays. Overlap values have a geometry lifetime, with full verification under the epoch-debug flag. The request is consumed only by a supported device density builder; unsupported upstream routes retain CPU normalization and cannot qualify as device-normalized in the harness. Optional pre-normalization NetCDF history output also preserves the original route. A four-byte status download remains until device error/control propagation is implemented. Its initial force, relaxation, NC, SOC/MAE and Fe54 regression passes; larger-case and performance validation remain. The default remains the validated host-normalization path described above.

The native checks compare sparse real/complex/spinor DM and energy-DM results with independent NumPy/SciPy contractions. They cover periodic phases, duplicate periodic images, truncated spectra, signed/zero occupations, simultaneous real spin slots, wavefunction export, stale-slot rejection, normalization and a host mutation between grid calls. End-to-end force, relaxation, density and magnetic gates remain the primary verifier.

## Remaining host boundaries

This is an integration milestone toward the specified architecture. The complete electronic state is not yet device-resident. Supported density builders retain eigenvectors, but density and energy-density matrices still return to CPU consumers. Potentials and Hamiltonian/overlap inputs cross the boundary. Hartree/XC, sparse Fourier assembly, mixing, final forces and stress stay in upstream CPU code. Occupations have an opt-in GPU path described below. The recorded transfer counts make these boundaries visible. Other diagonalization routes, including file-backed eigenvectors and spin spirals, are outside the new density-builder integration.

The optional [device occupation integration](OCCUPATION_VALIDATION.md) now retains first-pass spectra in a per-diagonalization bank, computes FD occupations/entropy on device and lends E/Q directly to density construction. Sampled-k vector solves leave that first spectrum intact. Explicit identity, completeness, geometry and single-consumer checks guard the bank; debug mode additionally rejects host E/Q mutations. The bridge still exports eigenvalues and Q for host consumers and reads a 32-byte result/status per FD call. Its phase counters expose these temporary boundaries. Fixed-spin and other unsupported occupation routes fail explicitly when enabled.

The additional [resident spectrum mode](SPECTRAL_RESIDENCY_VALIDATION.md) keeps E/Q off the host throughout SCF. Sampled-k builders retain all requested vectors and apply the existing occupation cutoff on device, avoiding a host band-selection scan. Completed banks may be replaced within the same geometry, then exported explicitly after SCF for existing host workflows. Ownership and export checks prevent stale, incomplete or duplicate publication. The runner rejects SCF E/Q transfers and missing geometry-cycle exports. Nine-case physics and CUDA/filesystem validation passes; full-residency status remains false.

The next architectural requirement is the [fully resident conventional baseline](GPU_RESIDENCY.md). Device ownership and migration of the remaining consumers must close the density/potential, XC/mixing and sparse-to-k-space handoffs; profiles determine the optimization order within that work. Extend existing upstream operations rather than create a second DFT implementation. Final force/grid work remains a separate measured target. Batching k points, persisting eigensolver subspaces, reusing directional states and precision experiments can support the resident architecture. Learned initialization is deferred until the conventional residency baseline passes its acceptance gates, and later predictions must still be corrected and verified by conventional SCF.

## Scientific and performance gates

Each run is isolated, input/pseudo hashes are checked, and failure/convergence state is independent of merely finding a total-energy line. Regression requires total energy per atom, Fermi energy, eigenvalues, total and atom moments, atom charges, forces, stress and full density-component arrays. SOC calculations compare total energies even when upstream includes SOC in the nonlocal energy instead of printing a separate contribution.

MAE comparison uses the energy difference itself, verifies identical non-directional inputs, and checks that the final moment remains within one degree of each requested axis. The present sweep is a numerical regression at fixed settings, not a claim of physically converged anisotropy. Structural relaxation additionally checks the final component-wise force tolerance and final coordinates.

Wall time includes process startup and final output. Component profiles use exclusive hierarchical times to avoid double counting. Raw timers are retained alongside classifications. Custom GPU counters cover explicit transfers, allocations and grid launches; library-internal counts are not inferred. Full CUDA activity tracing is still needed before claiming complete kernel/allocation coverage.

`native/execution.cpp` records successful explicit bridge copies by boundary and phase. Patched `siesta_forces` marks initialization, every SCF iteration, post-SCF work and state analysis/export; in-memory counters are written only at process shutdown to `remag-residency.json`. The runner requires marker coverage to match printed SCF iterations and transfer totals to match the solver/grid/density bridges. Reports distinguish all SCF traffic from iterations after the first in each geometry. Post-SCF and analysis can both contain output; these markers do not classify or measure filesystem calls. Library transfers, unified-memory migrations and file I/O are explicitly unknown, and strict residency remains false even when explicit counters are zero.

The optional filesystem diagnostic aligns strace records with phase wall-clock timestamps. Its SCF interval begins immediately after incrementing the iteration counter, including wall-time and input-option checks before the numerical timer. Parsing or completion gaps leave coverage incomplete. File syscalls, mappings and read/write bytes are counted separately; page faults and asynchronous writeback remain unmeasured. Diagnostic timing never qualifies speedups. All 16 normalization/control traces parsed completely and identified stdout/FDF writes during SCF. This audit is separate from the bridge's transfer accounting and excludes the external tracer and harness sampler.

The optional CUDA activity observer is a separate preload library, with weak phase/shutdown hooks in the bridge. Production runs do not link or load CUPTI. Requested memcpy and concurrent-kernel records stay in bounded host memory, with mandatory dropped-record/overflow/error counts and final synchronized delivery. Phase timestamps use CUPTI's clock. The harness reconciles whole-process observed copy volume against the bridge's explicit counts and separately reports additional bytes; event overlaps count conservatively in neighboring phases. A known-traffic executable validates array copies and four-byte scalar downloads before any traced DFT run. The [six-case observer validation](CUDA_ACTIVITY_VALIDATION.md) passes after moving finalization before CUDA teardown; generic batched solver loops pass only at size 64 so far. Unified-memory and mapped-host behavior remain unknown, and all instrumented timings are excluded from performance qualification.
