# Two-center integrals and final force residency

The shared GPU primitive now implements the pinned `matel_table_m:get_matel` evaluator and has isolated numerical qualification. `kinefsm` uses the T table, `overfsm` uses S, and both nonlocal projector routines use S. The qualified Fe54 production profile in run `20261006T170248Z` records 1.798 s in `nlefsm`, versus 0.129 s each in `kinefsm` and `overfsm`. These are single-run inclusive CPU observations, not an isolated GPU speedup measurement.

The current grid force path already computes orbital/core/neutral derivatives on GPU. Legacy D/E and other electronic exports remain for integral forces, SOC, and final analysis. A device two-center evaluator is the first dependency for migrating those consumers; it does not itself remove those exports.

## Pristine numerical reference

[`scripts/check_two_center.py`](../scripts/check_two_center.py) links the unmodified pinned `libsiesta.a`. It registers compact radial functions, uses upstream spline construction, spherical-harmonic Fourier expansion, and `matel_t%init` to build real S/T tables, then calls upstream `%get_matel`. It retains the actual reduced radial tables, coefficients, harmonic maps, registry offsets, query pairs/displacements, and all four output components.

The [CPU reference](../results/two-center-oracle-20261006/reference.json) contains eight fixtures and 18,500 queries. They cover s, spd, higher harmonics through product angular order 10, asymmetric registry subranges with nonzero harmonic bases, both displacement signs, the near-origin replacement, near-axis handling, spline knots, exact cutoff endpoints and adjacent floating-point values. [`verify_two_center_oracle.py`](../scripts/verify_two_center_oracle.py) reconstructs raw output hashes, checks table bounds and exact outside-cutoff zeros, and verifies 1,500 finite-difference gradients and 1,936 reciprocity elements. Maximum consistency errors are 1.693e-9 and 3.571e-11 respectively. These diagnostics do not replace the pristine outputs as the GPU numerical oracle. This synthetic corpus has no material table/neighbor ownership qualification yet.

## Required evaluator semantics

- `R12` points from function 1 to function 2. If its norm is below 1e-12, upstream replaces **only z** with positive 1e-12 and recomputes the norm. Output and derivative use this adjusted vector.
- The cutoff is inclusive: evaluate when `R <= RCUT(IG1)+RCUT(IG2)`. Outside it, all four outputs are exactly zero.
- For each harmonic pair, compute `IH = (IFLM1-BASE_SPHA1) + (IFLM2-BASE_SPHA2-1)*MAT_ROWS` in upstream's one-based indexing. Preserve the nested summation order across functions and angular terms.
- Determine each harmonic pair's `LMAX` from `ILMFF` before calling the spherical-harmonic algorithm. Upstream uses explicit formulas through order 2 and a different general branch above 2, including its near-axis convention. The existing orbital GPU helper supports only order 5; it cannot be reused unchanged for order-10 products.
- Use `FFR(0:NRTAB,1:2,JFFR)` and the exact spline interval/derivative arithmetic. Pinned `NRTAB=1024` and `DRTAB=pi/100`; do not resample or fit learned functions. Reduced table coefficients may carry signs and scaling.
- Preserve `DSDR += DSRDR*FFY*Y*X12/R + SR*FFY*DYDR` and FP64 arithmetic. The cutoff and spline range are distinct guards.

A device query API should borrow already staged immutable table arrays and coordinates, enqueue only kernels on the supplied stream, and write value/gradient plus a sticky device status. No allocation, copies, synchronization, logging, or scalar polling belongs inside that operation. Initial table construction/staging remains an explicit setup boundary. Invalid maps, range violations and nonfinite inputs need isolated fault cases, ordinary/captured execution, and long-stride coverage before material use.

## Consumer migration sequence

1. Qualify the standalone GPU evaluator against all retained pristine table outputs, with actual GPU output arrays and graph-node evidence. Add required index/status failure checks and a large query fixture.
2. Pack actual S/T tables from the disposable candidate's main table owner; keep upstream pristine. Stage once per table lifetime, and stage compact neighbor/projector topology per geometry. Evaluate overlaps and gradients on device. Shadow complete material arrays before making them authoritative, including both SOC directions and every relaxation geometry.
3. Move scalar nonlocal, kinetic and overlap contractions to retained D/E and a persistent force/stress/energy accumulator. For scalar nonlocal forces, preserve sparse-row multiplicities, periodic images, projector energies, paired atom updates and tensor order. Move the off-site SOC complex projector blocks with their own pristine oracle and material shadows; their spin reconstruction differs from dfscf.
4. Extend the shared accumulator across upstream's ordering: neutral pair forces, kinetic/nonlocal, grid terms, then overlap. Qualify total energies, forces, stress, relaxation, densities and directional MAE with direct controls before deleting a legacy export.
5. Migrate final analysis and remove exports only when no supported consumer remains. Full-corpus independent CUDA observation, requested-output variants, and broader physical convergence remain separate gates before learned SCF.


## GPU two-center primitive qualified

[Run 20261006T175529Z](../results/20261006T175529Z/REPORT.md) qualifies the isolated FP64 S/T two-center evaluator in `native/two_center.{hpp,cu}`. The 38 valid ordinary/strided/sticky comparisons have zero numerical difference from pristine `matel_t%get_matel` results at stored FP64 precision. This is numerical equality, not a claim about signed-zero bit patterns or performance.

The primitive preserves one-based registry/harmonic maps, reduced radial tables, coefficients and nested summation order, the positive-z 1e-12 near-origin replacement, inclusive cutoffs, exact spline arithmetic and spherical-harmonic product orders through 10. It handles asymmetric table bounds and nonzero bases. One kernel borrows staged tables and query arrays, writes values/gradients and maintains a sticky device status, without allocation, copies, synchronization or I/O inside the operation. Invalid queries produce defined zeros. The existing production orbital helper is unchanged.

Ordinary and captured execution run one and three replays with poisoned outputs before every replay. A 131,073-query fixture crosses the capped 1,024-block, 128-thread launch's strided tail. Captures contain one kernel and no forbidden nodes. Faults cover low/high query and harmonic indices, term bounds/order, unsupported angular indices, radial indices, cutoff/base descriptors, nonfinite coordinates/tables/coefficients, interpolation range, overflow, sticky status, empty expansions and invalid host configuration. Shape-derived allocations, staging, exports and poison coverage reconcile independently. These are isolated probe boundaries; no whole-process CUDA observer ran.

All eight fresh pristine CPU table fixtures also pass cutoff, raw-output hash, reciprocity and finite-difference checks. The one Fe2 force regression passes independent raw stdout/eigenvalue/RHO/DRHO comparison at 25 SCF iterations, with zero explicit transfers inside the electronic cycle. Eighteen retained-grid field checks pass. Local validation passes 75 tests. The single A100-SXM4-80GB allocation, driver 580.95.05, is stopped with zero tasks and an empty final container inventory.

No new material speedup or export removal is claimed.
