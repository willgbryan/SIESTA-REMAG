# Nonlocal force migration

The remaining nonlocal force consumer reads exported CPU density matrices. Its scalar and off-site SOC branches must migrate before those exports can disappear. The target is geometry/projector data staged before SCF, GPU overlap/gradient evaluation, contraction against retained device D, and accumulation into the same final energy/force/stress owner as kinetic, grid and overlap terms. No intermediate projector or contribution downloads belong in that production path.

## Pinned conventions

The executable specification is `upstream/siesta/Src/nlefsm.f` at the commit in `upstream.lock.json`.

- Scalar `nlefsm` adds all matching sparse density entries, including repeated column indices. Each entry adds its diagonal spins in source order. Its force contribution is `2*Di*epsilon*S_right*gradient_left`; the left atom receives its negative, the projector-center unit-cell atom receives its positive, and stress receives `displacement(j)*force(i)/volume`.
- Off-site SOC resets `Di` and assigns all four complex density elements at every matching sparse entry. Duplicate columns therefore use the last entry. This differs from the scalar branch and must be preserved.
- The eight-component density reconstruction is `D11=D1+iD5`, `D22=D2+iD6`, `D12=D3+iD4`, `D21=D7-iD8`. Operator contraction uses `V11*D11 + V22*D22 + V12*D21 + V21*D12`, including the same transpose convention for derivatives.
- The `l=0` SOC block uses the scalar projector directly. `split_sr_so` changes where its energy is reported, but its force always uses the diagonal density sum.
- For `l>0`, `calc_Vj_offsiteSO` combines both `j=l-1/2,l+1/2` blocks with the original Clebsch–Gordan coefficients and real-harmonic phases. The scalar/SOC energy split preserves the original signed mixed-epsilon heuristic, including opposite and zero signs. Its derivative includes the **full** nonlocal operator even when the energies are separated. The supplied right derivative is unused; forces differentiate the left overlap only.
- Actual neighbor selection, strict outer cutoffs, unit-cell/local-row restrictions, projector block order and periodic multiplicities remain separate material-geometry requirements. They are not established by isolated arithmetic fixtures.

## SOC projector arithmetic

`scripts/check_soc_projector.py` extracts the entire pristine `calc_Vj_offsiteSO` routine literally, compiles it locally, and retains exact input bytes and all 33 output values per query: scalar energy operator, real/imaginary spin operator, and real/imaginary derivatives in Fortran component order.

[The CPU reference](../results/soc-projector-oracle-20261006/reference.json) contains 64 fixtures and 263,680 queries: angular orders 1–5, both split modes, six epsilon-sign/zero pairs, self-pairs, zero overlaps/gradients, a 257-query launch edge and a 131,073-query strided tail. Changing the supplied right gradient leaves the pristine output unchanged. Source, wrapper, input and output hashes are retained.

[Independent reanalysis](../results/soc-projector-oracle-20261006/soc-projector-oracle-verification.json) constructs angular operators as separate complex matrices and contracts the real harmonic amplitudes with NumPy. Maximum discrepancy is 5.552e-17. Finite differences of the full operator agree with the pristine left derivatives to 1.475e-12; separating the energy leaves the full operator and force unchanged.

`native/soc_projector.{hpp,cu}` implements the isolated FP64 device operation for angular orders 1–5. It accepts caller-owned device buffers and a stream, performs one kernel launch, writes complete per-query results, and uses a sticky status for nonfinite arithmetic or the upstream symmetry guard. There are no copies, allocation, synchronization or I/O inside this operation. The standalone kernel is linked into its check library; its shared arithmetic helper is also used by the compact material shadow described below.

`--probe-soc-projector` runs pristine comparisons in ordinary and captured modes, poisoning every output before each of three graph replays. It covers empty batches, launch tails, nonfinite inputs, overflow, sticky status and unsupported host configurations. Full output arrays and mutated inputs are retained for independent reconstruction. [Run 20261006T202253Z](../results/20261006T202253Z/REPORT.md) passes all 168 scenarios and independent retained-array reanalysis with zero numerical difference from pristine Fortran at stored FP64 precision. All 144 mutated input arrays reconstruct exactly; all 80 captures contain one kernel and no forbidden nodes. The unchanged Fe2 force route passes raw scientific reanalysis, all 178 source and 667 component hashes verify, and the single GPU is stopped. ## Material geometry and ownership design

The pristine routines reuse each `Ski` overlap across many orbital pairs. Avoid expanding every pair into stored scalar inputs and 33-component SOC operators. Retain compact per-projector-center neighbor lists, orbital/atom mappings, projector blocks and the indices of their two-center overlap records. Scalar force selection uses `ikb`; off-site SOC uses the actual `koa`/`koa1:koa2` indexing. Preserve those source indices explicitly rather than assuming they are interchangeable.

Capture geometry during the existing matrix-only H0 preparation before SCF. Both neighbor selection and the S/T table registry are already available there. At final forces, regenerate or reuse the device overlaps, obtain left/right block views through the retained mappings, and evaluate/constrain the same scalar/SOC contractions without uploading D. Compare the staged topology with the actual grid sparse owner and reject stale geometry. The current two-center shadow can continue checking complete values and derivatives during material qualification.

The grid geometry's `lookup[row*no+column-1]` retains the last sparse entry. That matches SOC scatter semantics directly, but is insufficient by itself for the scalar branch. A scalar implementation can compute one weight per canonical sparse entry from retained D, adding all matching entries and their diagonal spins in pristine order. A temporary capacity-sized weight array preserves sparse electronic storage and avoids repeatedly scanning a row for every projector pair. Do not replace D with a dense electronic matrix. This compact sparse strategy is implemented by the material shadow qualified below; production substitution remains pending.

Extend the final-state lease between kinetic completion and the first grid consumer. The nonlocal lease must match the scalar/SOC spin layout, cannot overlap another consumer, and must complete before grid, overlap, analysis or geometry reset. The material shadow initially compares both energy channels and complete force/stress vectors with unchanged CPU results. Its reference transfers are diagnostic costs; production must remove them and extend the shared accumulator through all four consumer stages.
