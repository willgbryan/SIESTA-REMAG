# Device-controlled SCF integration contract

The opt-in `--device-scf` route replaces SIESTA's restricted serial electronic loop with a device-controlled cycle. The 32-state batched-Jacobi local solver passes both retained Fe54 failures and five fresh Fe54 calculations, while the original local solver remains unreliable on clustered spectra. Production qualification remains incomplete: the broader CUDA/filesystem-traced batch passes seven cases, then Fe16 faults under CUPTI before Fe54 runs. Independent tracing of the larger workloads and final GPU observables remain open. See [the solver experiment record](BLOCK_JACOBI_EXPERIMENT.md).

## Preserve the supported algorithm

Construct one execution graph per declared geometry/configuration lifetime. Stage immutable topology, overlap, k points, occupations configuration, initial electronic matrices and mixer/convergence settings before entering SCF. Use a nondefault CUDA stream throughout. Allocate all scratch, diagnostic history and error records before capture; bounded diagnostics need at most the configured maximum SCF iterations. The current default-stream bridge adapters cannot simply be wrapped in capture: their host ownership transitions and scalar downloads must be separated from device operations.

Each device iteration must:

1. Save H/D/E inputs as Hold/Dold/Eold, preserving the optional initial-EDM rule.
2. Assemble and solve the existing spin/k blocks, publish the first spectrum, compute occupations, and build/normalize sparse D/E. Initially preserve the sampled-k two-pass convention: occupations use the frozen first-pass spectrum even when vectors are solved again. Retaining every k-point eigenvector is a later memory/performance choice, not a prerequisite for residency.
3. Build Hamiltonian seeds, contract the density onto the mesh, evaluate Hartree/PBE, and add the potential matrix directly into owned H.
4. Compose energy seeds, reduce energies/charges/residuals, evaluate the existing convergence plan, and retain the iteration's diagnostic record on device.
5. Apply stable Pulay when `mix` is set, including the maximum-iteration nonconverged step. Preserve the first-mix exception: history still advances but H takes Hold plus residual when the configured first mix is disabled.
6. Continue only while the convergence result requests it and every component status is successful. Error and nonconvergence remain explicit outcomes; they must never be mistaken for success.

Use the qualified component conventions: strict residual thresholds, minimum iteration count, latched energy criteria and fresh epoch reset. Keep component errors sticky within a cycle. The isolated blocked-solver check continues across independent failed inputs to verify reset; an SCF consumer must instead stop at its first failed solve.

## Interfaces that still need migration

`ScfConvergencePlan`, `ScfScalarsPlan`, `HamiltonianSeedsPlan`, `PulayPlan`, FD occupations and grid-potential plans already expose device operations. Their production adapters still own important host state. New executor interfaces must stage configuration once, expose stable device buffers, and advance ownership/error/iteration records on device. In particular:

- `sparse_state.cu` keeps the stage, iteration, borrower flags and counters on CPU and returns a 144-byte summary plus four-byte mixer status.
- `occupation_state.cpp` freezes the first spectrum and tracks one-use consumers on CPU; its 32-byte result export must become a final-cycle export.
- `density_matrix.cu` has three reusable vector slots, host-request state, host normalization completion and status handling. Those contracts must be retained in device form.
- `grid.cu` and `hamiltonian.cu` combine reusable geometry storage with host launch/ownership logic. Capturable operations need explicit stream and buffer arguments.
- `grid_potential_state.cpp` returns a 224-byte scalar/stress record and closes the mesh lifetime at SCF end. Final force consumers require that mesh lifetime to remain available.

Production integration should first replace the loop for the existing restricted serial PBE/FD/Hamiltonian-mixing settings and reject unsupported consumers before execution. Do not silently fall back to host numerical work in a run advertised as device-controlled.

The new borrowed views are preparation interfaces, not a completed ownership handoff. In particular, legacy H/S completion counters, density `active/finished` flags and spectrum one-use flags are still advanced by host adapters. A whole-cycle executor must explicitly acquire the geometry/configuration lifetime and its H/D/E/EQ buffers before launch, prevent legacy consumers from running during that lifetime, and publish final status/ownership after completion. It must not call legacy `end` routines that expect per-iteration host callbacks which the graph has bypassed. Geometry changes must destroy or finish the old executable before any backing allocation is reused.

Use the existing pre-SCF `setup_H0` / `setup_hamiltonian(0)` boundary to stage available geometry and initial electronic data; remaining diagonalization/mesh configuration needs an explicit preparation path. Do not disguise a host-controlled first numerical iteration as setup. The measured device cycle must cover its first accepted SCF iteration. Preserve the sampled-k frozen first spectrum in a distinct E bank: second-pass eigenvalue scratch must never overwrite the E used for occupations and energy-DM. Device failures must stop before the next consumer; a final host error report is allowed only after the measured cycle has ended.

## Device control component qualification

`ScfControlPlan` now appends convergence, conditional stable Pulay and bounded diagnostic retention to a caller's iteration graph. An outer device while-loop consumes its `continue_loop` result. It preserves the first-mix history update/bypass, performs the maximum-iteration nonconverged mix, stops on producer/mixer errors and keeps errors sticky until a new explicit epoch. A completed epoch is inert on replay. Invalid configuration or mutation inside an epoch stops the component. Diagnostic capacity is fixed before capture and must cover the configured maximum iterations.

The 75 fixtures pair pristine upstream convergence decisions and stable-Pulay results, include every nonempty criterion mask, first-mix settings, minimum iterations, strict thresholds, repeated epochs, forced errors and invalid configuration. All pass on both driver 580.95.05/A100-SXM4-80GB ([first run](../results/20261006T061050Z/REPORT.md)) and driver 610.57.04/A100-SXM4-40GB ([second run](../results/20261006T061806Z/REPORT.md)). Each run covers 441 selected iteration/terminal-replay records. Maximum mixed-vector error is 2.499e-16; all decisions and retained diagnostic bytes agree. Each graph has 25 inventoried nodes and no forbidden host/copy/allocation node. Both runs verify 82 source hashes and 309 component fixture/output/oracle/checker hashes.

The checker stages scalar/residual producers and launches nested control graphs; it does not compute density or grid physics. Run [20261006T065114Z](../results/20261006T065114Z/REPORT.md), on A100-SXM4-80GB/driver 580.95.05, now passes all 75 control fixtures both untraced and under the memcpy/memset observer. All measured graph regions have zero H2D/D2H bytes, including first iterations and repeated epochs. Four positive/negative observer calibrations pass. The [raw-trace verification](../results/20261006T065114Z/conditional-transfer-verification.json) reproduces every activity summary and hashes the evidence. This scope excludes complete kernel coverage, managed/mapped host memory, CPU work and filesystem I/O. The same run passes all 36 blocked-solver transfer scenarios; all 86 source and 420 component evidence hashes verify.

Profiling faults on driver 610.57.04 remain unqualified; calibration now skips that known failing combination instead of repeating the fault. Use `--probe-scf-control` for the optional isolated suite; unchanged control checks need not repeat in every SIESTA batch. No production SCF boundary is removed by this isolated component yet.

## Capturable assembly interface

The production H/S adapter now calls `assemble_hamiltonian_device` with an explicit stream and a borrowed immutable geometry view. Its numerical kernels and sparse contribution order are unchanged. Initial geometry validation remains outside capture; the device operation only clears and assembles matrices. The caller must finish device work and destroy its graph before ending or invalidating the geometry owner. The host adapter continues to use the default stream, while the new checker captures the same operation on a nondefault stream over three pre-staged H inputs.

All eight real/complex/NC/SOC and Gamma/sampled-k capture scenarios pass, with maximum matrix error 2.483e-16 and no forbidden graph nodes. The [nine-case SIESTA regression](../results/20261006T062841Z/REPORT.md) passes all 46 native checks, both MAE comparisons, 18 CUDA/filesystem coverage checks and 84 source hashes. Recorded MAE differences agree exactly. The candidate traces have zero steady H2D but retain 353,456 scalar/library D2H bytes. The relaxation trace also records three steady filesystem calls reading one byte from `/proc/sys/vm/overcommit_memory`; mappings remain separately counted. Thus this run does not establish zero steady I/O. This interface does not by itself replace the outer SCF executor.

## Density interface qualification and remaining adapters

`density_matrix.hpp` exposes borrowed immutable topology plus stream-aware vector transpose, zero-fill, sparse D/E accumulation and charge normalization. The tiled transpose copies real or complex values without arithmetic/conjugation. The production adapter retains one-shot vector ownership and its four-byte normalization-status export, but removes the per-accumulation global barrier because producers and consumers share the default stream. Accumulation timing now explicitly measures host enqueue time. The graph checker stages all inputs, captures these same operations, varies occupations across replays and checks normalization failure/recovery; exports happen only after all launches.

All 12 density capture scenarios pass across 48 replays, including 12 expected normalization failures and later recovery, with maximum D/E error 2.776e-17 and no forbidden nodes. The [same nine-case regression](../results/20261006T065114Z/REPORT.md) passes all 58 native checks, both MAE comparisons and 18 full SIESTA trace-coverage checks. Its 376 candidate iterations retain 358,384 steady scalar/library download bytes, zero steady uploads and the same three relaxation filesystem calls. Density graph inventories/numerical checks do not independently establish component activity coverage; the independently traced components above are control and the blocked solver.

`grid.hpp` separates density-to-mesh and potential-to-Hamiltonian contractions from host geometry staging and ownership. Both use explicit device buffers and a caller stream, with unchanged FP32 basis storage, periodic folding and SOC block arithmetic. The potential operation accepts a device volume scalar. Eight capture checks vary D/V/H/volume across 24 replays, cover 1/2/4/8 sparse spin components and two basis configurations, and export only after all launches. All pass with maximum error 2.221e-16 and no forbidden nodes. Mutation and geometry invalidation guards also pass. The same batch exposes the existing energy-seed compositor as a stream-aware device operation, preserving producer-error propagation.

The [grid and energy-handoff regression](../results/20261006T071319Z/REPORT.md) passes all 68 native checks, nine upstream comparisons, both MAE comparisons, 18 complete SIESTA CUDA/filesystem coverage checks and 88 source hashes. Across 398 candidate iterations, steady uploads are zero; 368,240 scalar/library download bytes and three relaxation filesystem calls reading one byte remain. The H/S, density and grid captures are numerical/node-inventory checks, not independent activity coverage. Production still uses the host-controlled SCF loop.

## Composed cycle executor under validation

`ScfCyclePlan` now constructs an entire bounded electronic cycle: sparse H/S assembly, blocked generalized solves, FD, D/E accumulation and normalization, Hamiltonian seeds, density/grid/PBE/Hartree, potential assembly, energy/scalar reduction, convergence and Pulay. It uses one nondefault stream and device conditional error gates. Gamma retains each spin block's vectors through occupations; sampled k points repeat the vector solve into separate spectral scratch while preserving the first E bank. Initial H/D/E is never used for library warmup. Completed or failed graph replays are inert. All storage and diagnostic capacity are fixed before capture.

The plan accepts exclusively leased device bindings independent of the legacy adapters. It was initially linked only into its isolated checker. The production handoff pilot below now links it into the opt-in SIESTA route. Construction validates device configuration before the first accepted iteration; failed producers stop downstream consumers. Partially updated scientific arrays are invalid after failure, while the sticky producer status remains available. A new cycle/geometry requires a fresh plan.

The checker constructs synthetic full sparse topologies and meshes, and compares whole cycles with SciPy generalized diagonalization plus pristine upstream FD, Poisson/GridXC, seed/SOC arithmetic, scalar reductions, convergence and stable Pulay. Twenty local reference sequences cover real/complex, collinear/noncollinear, onsite/offsite SOC, Gamma/sampled k points, first-mix settings, minimum iterations, exhaustion and clustered meshes. Eight forced failures check early opacity, downstream suppression and terminal replay. The [first single-GPU cycle batch](../results/20261006T074753Z/REPORT.md) compiles and passes all 28 numerical/error scenarios and 80 iterations, with maximum scalar error 1.497e-14. Four observer calibrations pass, but a Python return-value unpacking error prevents cycle transfer workers from launching; copy coverage is still unqualified. These fixtures are not material calculations or a production handoff qualification.

Complete bounded per-step Fermi, normalization, seed-energy and grid-energy/stress records are retained; coupled checks include solves crossing the 64-state block boundary. The [expanded batch](../results/20261006T075424Z/REPORT.md) passes all 32 checks and 96 iterations, with maximum diagnostic error 9.948e-14. Driver 610.57.04 prevents conditional profiling in that run. The later qualified run below adds independent filesystem tracing and completes copy coverage. The production handoff still needs pre-SCF geometry/configuration staging, exclusive owner acquisition/release, diagnostic-to-log formatting, and explicit final scalar/state publication. The bridge must also publish the final Hold/Dold/Eold snapshots when downstream upstream consumers require them, retain the final device mesh/potential for later GPU force work, and use identical staged k-point values for assembly and density phases. Gamma phase vectors must be zero. Initial EDM storage must be explicitly initialized when the upstream EDM criterion is disabled. These are handoff requirements, not behavior inferred from legacy per-step counters. Final GPU forces/stress remain outside this plan.

The [complete-cycle qualification](../results/20261006T080125Z/REPORT.md), on A100 80GB PCIe/driver 580.95.05, passes all three 32-case suites: untraced, CUDA memcpy/memset tracing, and separate selected-filesystem tracing. Each suite completes 96 accepted iterations plus eight expected failures. Maximum scalar error is 6.218e-14; maximum per-step diagnostic error is 1.386e-13. Every terminal replay is inert; no forbidden graph node appears. All measured CUDA regions have zero H2D/D2H bytes. All filesystem regions have zero selected file operations and zero mappings. Both measurements include the entire first accepted iteration and terminal replay, after explicit staging and before final export.

[Local raw CUDA reanalysis](../results/20261006T080125Z/conditional-transfer-verification.json) reproduces 32 cycle worker traces and four observer calibrations; 83,565 events use the qualified unique graph-scope attribution. [Filesystem reanalysis](../results/20261006T080125Z/cycle-io-verification.json) reproduces all 32 raw syscall traces and phase intervals. All 92 source and 219 component evidence hashes verify. The independent Fe2 force pair and 68 native checks pass. These results qualify the synthetic composed executor, not its production handoff, full material trajectories, final GPU observables, complete kernel activity, managed/mapped host accesses, page faults/asynchronous writeback or performance. The exact scope and maxima are retained in the [cycle summary](../results/20261006T080125Z/cycle-validation-summary.json).

## Measurement and output

A single graph launch can contain a whole electronic cycle, so host SCF markers no longer equal individual iterations. Trace metadata must distinguish cycles/launches from the device iteration count. Require zero H2D/D2H across the entire graph execution region after staging; this is stronger than classifying only iterations after the first. Record device iteration count, convergence state and bounded history, and export them after the SCF boundary. Reconstruct the conventional diagnostic log from those records so numerical comparisons remain reviewable. Graph construction, warmup and reset must not accidentally advance the accepted scientific state.

Conditional-body memcpy/memset attribution passes within the qualified single-region graph scope above. Complete kernel coverage and other drivers remain separate instrumentation gates. Whole-process totals, graph inventories and mapped-host/managed-memory limitations must remain explicit; absent correlation is not a zero-transfer result. Production qualification retains the original scientific corpus, MAE direction checks, forced-error tests, first-mix/reused-geometry coverage, and untraced performance comparisons.

## Production handoff pilot

`--device-scf` now replaces the restricted serial electronic loop with one complete device cycle. Initial DHSCF stages geometry constants, existing caches hand over exclusive leases, and legacy consumers cannot use leased H/S, density or mesh geometry. The owner stages initial electronic arrays and immutable convergence/mixing settings before graph construction. No accepted iteration runs on the host as preparation. The first accepted iteration is included in the measured region.

The owner closes the SCF region before status/scalar/array export, publishes H/Hold/D/Dold/E/Eold and the frozen E/Q bank, and releases the graph before any borrowed allocation. SIESTA replays retained diagnostics through its normal energy/convergence reporting after execution and checks the replayed decisions against device results. It preserves upstream final force/analysis consumers on the CPU. The mesh is currently released at final publication; retaining it through GPU force work is still required. Unsupported consumers/options fail before launch. The corpus disables per-step timer splitting in both reference and candidate inputs; scientific settings and tolerances are unchanged. Whole-cycle execution time and its mean per accepted iteration are reported separately from host iteration timers.

The [first production pilot](../results/20261006T083311Z/REPORT.md) passes Fe2 forces in 25 iterations, matching the reference iteration count. Every scientific gate passes: printed energies, forces, stress, moments and charges agree at their output precision; maximum eigenvalue difference is 1.00e-7 eV and raw-density difference 2.981e-8. The entire device cycle has zero explicit copies. All 68 native checks, upstream component preflights, 75 local tests and 94 archived source hashes pass. Library transfers, selected filesystem activity, reused geometries, the rest of the magnetic corpus and repeated performance are not qualified by this pilot.

The [first broad handoff run](../results/20261006T083554Z/REPORT.md) passes eight of nine production pairs, including Fe2 relaxation, Gamma non-collinear/SOC, sampled-k FePt x/z and Fe16 non-collinear. Both direct MAE differences agree at output precision. The whole-cycle component passes 32 scenarios. Fe54 aborts before its first accepted iteration with blocked-solver status 3 (local eigensolver failure), on A100-SXM4-80GB/580.95.05. This run is explicitly partial. Native cycle accounting is absent for the aborted process, so its transfer count is unknown.

The [Fe54 diagnostic retry](../results/20261006T085932Z/REPORT.md) passes all scientific gates in 47 iterations on A100 80GB PCIe/580.95.05. Its CPU reference is reused only after input, pseudopotential and executable-hash verification; cross-allocation speedup is unqualified. Numerical algorithms and tolerances are unchanged. Post-failure H/S and solver-history capture was added, but no failure occurred to capture. This success does not resolve the intermittent failure. A first-local-error record and repeated same-instance runs are the next diagnostic; diagnostic export occurs only after closing the SCF region.
