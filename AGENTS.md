# Project rules

- **Current goal, revised by the user on 8 October 2026:** deliver a measurable end-to-end speedup over upstream GPU SIESTA for magnetic materials through GPU-first execution and purpose-built GPU data structures. Fully relativistic, spinful noncollinear/SOC workloads remain the north star. Use upstream SIESTA directly as the numerical validator. This priority supersedes earlier requirements to complete exhaustive residency certification or elaborate preparation/audit infrastructure before delivering optimizations.
- User-authorized Modal capacity is **one GPU instance total at a time**. Expansion requires explicit permission from the user. Use `scripts/run_modal.py`; never add concurrent GPU functions, multiple-GPU requests, parallel maps, warm pools, or overlapping app launches.
- Upstream SIESTA is the executable specification. Keep `upstream/siesta` unmodified and pinned to `upstream.lock.json`. Apply candidate changes only to disposable source copies via the integration patch.
- Profile representative end-to-end workloads before prioritizing optimizations. Keep raw evidence and the machine-readable ledger; never claim speedup for a failed or scientifically non-equivalent calculation.
- **Future writeup and visuals, requested 8 October 2026:** preserve results from the work already planned for a later site / "Project 14"-style writeup. Use the existing result files and ledger to retain individual timing repetitions, workload sizes and physics/settings, baseline identity, hardware/software versions, scientific pass/fail status, and available stage timings, memory and transfer measurements. Keep concise before/after optimization notes and links to the exact measured source/results so figures and architecture diagrams can be reconstructed later. Distinguish verified upstream-GPU comparisons from incremental or provisional results, retain failed attempts, and leave unavailable measurements unknown. Do not add benchmark runs, instrumentation, reporting infrastructure or retrospective data collection solely for visuals; creating the site and graphics is deferred until the build is complete.
- The primary performance competitor is upstream SIESTA's existing GPU path, as clarified by the user on 7 October 2026. Establish a matched, scientifically verified comparison with GPU-enabled upstream ELPA/native and applicable ELSI routes, confirming actual GPU execution and using reasonable solver/thread settings. CPU upstream remains the numerical oracle and a secondary timing baseline. CPU speedups and comparisons with our own earlier CUDA path do not establish a gain over upstream GPU SIESTA. Run all contenders sequentially within the one-GPU limit.
- The user withdrew Gold–water on 7 October 2026. Use magnetic systems for the upstream GPU comparison. Fully relativistic, spinful noncollinear systems are the primary correctness and performance target; prioritize complex spinors, full spin–orbit coupling, forces/stress and directional magnetic energy differences. Keep collinear and scalar-relativistic cases as regression coverage. Verify the actual SOC approximation and relativistic pseudopotential content rather than inferring full support from a case name. Performance gains on simpler spin layouts must still be measured.
- Convergence, completed execution, required observables and input provenance are mandatory. Unknown telemetry is `null`, not zero. Compare MAE differences directly and verify final moment directions.
- Design persistent device storage, sparse layouts, complex spinor/SOC representations and reuse around the actual GPU workload. Preserve upstream numerical semantics and requested outputs; the internal data structures may change to improve locality, batching, ownership and end-to-end runtime. Remove expensive transfers and I/O where measurements justify the work.
- GPU residency is an engineering means to speedup. Exhaustive proof of zero managed/mapped-memory traffic or filesystem activity is not a delivery prerequisite. Keep unavailable measurements unknown, but do not create a new observer/audit workstream to certify their absence. The prepared v114 NVBit diagnostic is deferred and must not launch under the current priority.
- Keep validation lean: run upstream SIESTA and the candidate on equivalent representative magnetic inputs, compare the relevant scientific outputs with the existing numerical tolerances, and measure end-to-end time. Use targeted kernel checks only for a concrete numerical risk or observed discrepancy. Reuse existing checks; do not expand synthetic controls, provenance frameworks or staged prerequisite chains as routine work. Test on Modal when GPUs are required.
- Prioritize completing the already-running upstream GPU comparison, a focused nonparallel SOC regression, and measured production integration of useful existing staged changes. Choose subsequent work by observed bottleneck and magnetic relevance, not by the number of remaining host boundaries or prepared tests. Learned SCF remains deferred while the conventional performance baseline is being established.
- Document capability limits and unvalidated physics/settings explicitly. Regression inputs are not production convergence studies.
