# Benchmark corpus

The source release includes [selected benchmark records](evidence/README.md).
Paths and links into `results/` below refer to the separate local evidence
archive; full material outputs and externally obtained pseudopotentials are
not bundled in Git. See [running instructions](../docs/RUNNING.md) for the
reproduction boundary and the distinction between CPU and GPU baselines.

Inputs are generated by `remag prepare`; pseudopotentials are copied from the pinned upstream `Tests/Pseudos` directory, retaining filenames and hashes in each manifest. Generated inputs are immutable run inputs, kept under ignored `benchmarks/generated/`.

| Cases | Atoms | Coverage |
| --- | ---: | --- |
| `fe2_collinear`, `fe16_collinear`, `fe54_collinear`, `fe128_collinear` | 2, 16, 54, 128 | bcc iron, metallic collinear SCF; real gamma and complex k-point solvers |
| `fe2_noncollinear`, `fe16_noncollinear` | 2, 16 | tilted spin initialization, complex spinor density |
| `fe2_noncollinear_gamma`, `fept2_soc_gamma_x/z` | 2 | Gamma-specific spinor density builders and SOC conventions |
| `fept2_soc_x/z`, `fept16_soc_x/z`, `fept128_soc_x/z` | 2, 16, 128 | tetragonal FePt, full off-site SOC, paired directional energy differences |
| `fe2_forces` | 2 | displaced atoms and nonzero forces |
| `fe2_relax` | 2 | CG structural relaxation to 0.01 eV/Ang component-wise force tolerance |

Fe uses `Fe_nc.psf`; FePt uses `Fe_fept_SOC.psf` and `Pt_fept_SOC.psf`. All use GGA-PBE and SZP. The upstream distributions supply test pseudopotentials, not a certification of production pseudopotential quality. Inputs and checksums are retained with each result so results never silently mix different pseudos, basis choices or convergence settings.

FePt smearing is 1000 K for stable small-cell regression; iron uses 300 K. At the initial 300 K FePt setting, the z calculation did not converge in 200 SCF steps and was rejected. That failure is development evidence, not a physical result. The small corpus intentionally includes a difficult metallic/SOC family, but smearing and k-point convergence need further work before MAE values are used scientifically.

Cells with at least 30 atoms use `DM.Tolerance=1e-7` and `SCF.H.Tolerance=1e-6 eV`. The tighter SCF thresholds address accumulated uncertainty in the extensive total magnetic moment; the comparison gate remains 1e-4 Bohr magnetons for the whole cell. Smaller fixtures use 1e-6 and 1e-5 eV respectively. Every generated input records its actual values and checksum, including earlier failed parameter choices.

The recent matched GPU comparisons use the tighter retained DM 1e-9 / H 1e-8 eV input variants. The defaults above describe `remag prepare`; always use the exact measured input and manifest when reproducing a reported result.

Additional material fixtures currently live with their measured experiments:

- Sourced 40-atom Fe4N has complete pristine CPU references. The GPU collinear cuSOLVER-local fallback passes; the tested noncollinear settings remain unqualified.
- Sourced 16-atom Fe3C (cementite, AMCSD 0019113) has completed pristine collinear/noncollinear CPU reference runs in `carbide-local-reference-v168-20261009T164908Z`. Both current-production GPU comparisons pass, including forces/stress and raw matrices, with maximum saved-DM error 1.586e-8 against 1e-7. This initial qualification did not measure upstream-GPU speedup. Later collinear and noncollinear comparisons are included in the [selected evidence](evidence/README.md#expanded-magnetic-campaign-10-october-2026); no full-SOC claim follows. See [direct comparison](../results/carbide-gpu-v169-20261009T170851Z/upstream-comparison.json) and [retained structure and inputs](../results/carbide-local-reference-v168-20261009T164908Z/inputs).

These Fe4N/Fe3C fixtures use existing nonrelativistic upstream-test pseudopotentials and coarse regression settings; they do not establish full-SOC or production materials accuracy.

- Sourced 12-atom Fe2B passes direct pristine full off-site SOC x/z comparisons with the v163 GPU implementation, using fully relativistic PBE PSML pseudopotentials. Science, requested exports and final moment directions pass; MAE is -0.001622 eV in both implementations at printed precision. See [qualification and limits](../results/boride-gpu-v173-20261009T202117Z/capability-qualification.json). That capability record does not establish an upstream-GPU speedup.
- Sourced 32-atom Fe5PB2 passes direct pristine full off-site SOC CPU/GPU x/z comparisons with the v175 implementation, using fully relativistic PBE Fe/P/B PSML files. Science, requested exports and final moment directions pass; direct MAE is −48 micro-eV in both implementations at printed precision. The published GGA-SP structure and tight regression settings are retained. See [qualification](../results/candidate-magnet-gpu-v179-20261009T222951Z/capability-qualification.json). No upstream-GPU timing comparison is claimed.

The normal runner accepts these retained input directories directly. For example, to reproduce the qualified carbide CPU input without regenerating or changing its settings:

```sh
.venv/bin/remag run \
  results/carbide-local-reference-v168-20261009T164908Z/inputs/fe3c16_collinear \
  --executable build/upstream/Src/siesta \
  --output benchmarks/generated/fe3c16_cpu_reproduction \
  --threads 1 --timeout 1800
```

Use a fresh output directory for each calculation. This example reproduces the numerical reference; local CPU wall time is not an upstream-GPU performance baseline. The matching GPU implementation and runtime settings are identified by the [v169 capability record](../results/carbide-gpu-v169-20261009T170851Z/capability-qualification.json) and [run metadata](../results/carbide-gpu-v169-20261009T170851Z/metadata.json). GPU launches continue through `scripts/run_modal.py`, which enforces the single-allocation rule.
